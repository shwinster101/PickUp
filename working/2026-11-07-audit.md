## Findings, ranked (materiality × risk)

1. **The account ladder cannot work in production as configured (B2).** "Keep this account" and "Played
   before? Sign in" both need mail. Supabase's built-in mailer "will refuse to deliver messages to addresses
   that are not part of the project's team" unless custom SMTP is set ([Auth SMTP docs](https://supabase.com/docs/guides/auth/auth-smtp));
   the repository configures none. A mail that did go out would redirect to the Site URL `/OpenCourt/`
   (404): the provisioner run of 2026-10-18 used that URL, and a re-run would not change `site_url`
   (it sets it only when empty or `localhost:3000`). The page is honest about the failure (the raw error is
   shown), but the feature is dead for strangers. *Unverified on the project itself: the owner may have set
   SMTP or the URLs in the dashboard without a record.*
2. **Every shared signal is free to fake (B3).** Anonymous identity costs nothing (Supabase's default caps
   anonymous sign-ins at 30 per hour per IP; no CAPTCHA). Probes on a throwaway database
   (`working/2026-11-07-audit-probes.sql`):
   - P5: 10 fresh anonymous sessions → 180 reports accepted → **18 of 18 public courts read Full**, live, for 90 min.
   - P4: one session → **50 pickups** on one court (the map badge reads 50); `create_pickup` has no limit.
   - P3: a stranger sent friend requests and invitations to **every profile** (no friendship needed to invite).
   - P2: one person with three anonymous sock puppets → **10 wins + 10 MVPs, score 50, in 31 ms**
     (`create_pickup` accepts a start 15 min in the past and `record_result` closes it at once).
   - The note under a live report says "Reported N min ago **by a player on the ground**"; nothing checks
     presence (the two-browser proof, run in a data centre, produces that exact line).
3. **No usage is measured (B7).** The only usage gate in the plan (FOUNDATION §8) cannot be evaluated, and
   five passes of people-flow features were built ahead of any evidence that a non-owner uses the finder.
4. **The Free-plan pause has no owner (B4/B1).** A week of low activity pauses the project until someone
   restores it in the dashboard. Last recorded activity: the proof runs of 2026-10-18. Whether the
   minute-by-minute `pg_cron` job counts as activity is not documented in what was reachable here. When
   paused, the page falls back honestly ("Backend unreachable · bundled data …"); the pickups section used
   to say "not configured" (patched).
5. **A user who ever organised a pickup cannot be deleted (B4).** P1: deleting the auth user fails on
   `pickups_organiser_id_fkey` (23503). This blocks a deletion request and the clean-up of the proof's
   throwaway users in production.
6. **Nothing gates a deploy (B5).** A push to `main` that breaks JSON or JS ships; the 182 SQL assertions and
   the browser checks run only by discipline. `pages.yml` also publishes the whole repository (`working/`,
   `test/`, `scripts/`); harmless while the repository is public.
7. **The proof pollutes production (B4).** `test/e2e/README.md` told the reader to run it against the live
   page; it leaves a live "Open" report, a pickup with two test players, and two undeletable users.

**Next tier (real, smaller):** supabase-js loads from jsDelivr with no SRI (computed from the npm tarball,
unverified against the CDN: `sha384-0w2KAL2YHP6wKOkUDzkCDGgVvfmHnj02DHeQ6XcHOgTfFsGyonKOpShMH1x6nk9o`; it
also lazy-loads `591.supabase.js`); every clock in the page is the device's (heuristic hours, pickup times,
the theme's UTC date), not Los Angeles'; the Maps key has no recorded quota or budget alert now that billing
works; `push-to-github.sh` would `git add .`, rename the current branch to `main` and push; the Actions
in `pages.yml` run on deprecated Node 20 (warning in run #10); Supabase's Security Advisor will flag
`courts_live`, `open_pickups` and `player_standing` as security-definer views (intended, undocumented for
the owner); `test/e2e/__pycache__/*.pyc` is tracked; no privacy notice although emails are collected.

## Decision points (the owner's)

1. **Make the account ladder real or hide it.** Either custom SMTP (Resend, Brevo, Postmark …) plus Site URL
   `https://shwinster101.github.io/PickUp/` and `/PickUp/**` in Redirect URLs, or hide "Keep" and "Sign in"
   until then. A product call: hiding costs the account feature; SMTP costs a provider account.
2. **Choose the abuse posture.** Options, cheapest first: per-actor limits in SQL on `create_pickup`,
   `invite_to_pickup` (friends only?), `send_friend_request`; Supabase CAPTCHA on anonymous sign-in;
   standing that counts only games with ≥ 2 non-anonymous players, or a start time in the past by ≥ 30 min;
   report wording without "on the ground", or a geofence that makes it true.
3. **Measure demand before building more.** One query a week in the SQL editor (reports, pickups and
   profiles excluding the proof's users) or a privacy-friendly counter; then decide what Phase 5 waits on.
